# 显式初始化

只在用户明确初始化、注册、验证或切换 LearnEverything Vault 时读取本文件。

## 边界

- init 是可重跑的数据控制操作，不开始学习、不做起点诊断，也不创建 knowledge、source 或
  learning record。
- 路径、偏好回答和自由讲述在最终计划确认前都不写入。
- 用户中断、取消、沉默或修改尚未确认的答案时零写入。
- 普通学习缺少 Vault 时不进入完整问卷；只有完成后要保存，才执行必要的路径初始化子集。

## 首次使用时怎样解释选项

不要假设用户理解 Skill 的数据模型或 `managed/true` 一类内部值。首次展示一组选项时：

1. 先用一句话说明这项设置控制什么；
2. 每个选项都用结果导向的名称开头，再把内部值放在括号中；
3. 说明选择后会发生什么、不会发生什么，以及以后能否重配；
4. 推荐项给出简短理由，并允许用户直接回复“使用推荐设置”。

不能只列术语或代码让用户猜含义。多组选项可以在同一轮收集，但必须分开解释，不把说明压成
一行密集菜单；已经明确理解或主动指定内部值的用户可以得到更简洁的版本。

## 先选择 Vault

只读检查当前 locator 后，让用户从以下模式中选择，并显示 canonical 绝对路径：

1. 保持并验证当前 Vault；
2. 新建独立 Vault（推荐）；
3. 注册已有文件夹或 Obsidian Vault；
4. 切换到另一个已初始化 Vault。

相对路径和 `~` 必须先规范化再展示。已有 active Vault 时显示旧路径和新路径。切换不复制、
迁移、合并或删除旧 Vault；目标配置需要修改时必须进入同一预览。

已有目录注册前说明：除明确忽略的目录外，所有可见 Markdown 都参与 stem、链接和 backlink
解析。只读扫描后可以建议忽略大型无关子树，但必须逐项展示并确认，不能为了让 lint 通过而
自动隐藏问题。

## 可选学习指导

先说明 Learning Guidance 的用途：它只保存未来跨主题仍有用的教学行为，例如默认先看例子、
希望少测验或需要怎样呈现公式；它不是能力评估或学习者标签。暂不设置不会关闭学习、知识检索
或已完成学习的保存，只表示没有额外的长期教学默认，之后随时可以重配。

再统一提醒：Learning Guidance 是本地明文 Markdown；Git、同步和备份可能保留历史。清空当前
页面不等于彻底擦除这些副本。

用户可以选择：

- **暂不设置/修改（推荐）**：首次 init 不创建空 Learning Guidance 页面；重跑时保留现有设置。今后仍按当前
  主题和用户当下要求教学，也仍可保存完成且确认的学习。适合先实际学几次，再决定哪些要求
  值得作为长期默认。
- **快捷选择**：用至多四个简短问题设置常用默认；每组都可以跳过，回答只在预览确认后整理成
  自然语言规则。
- **自由讲述**：用户直接说明长期希望怎样讲、哪些方式应避免或需要哪些可访问性适配；Skill
  只提取可执行且面向未来的行为，并在写入前展示整理后的具体文字。
- **快捷选择后补充**：先用菜单快速定大方向，再用自由文字增加条件、例外或菜单未覆盖的要求。

快捷选择最多显示四组，每组默认单选，也可以不答：

| 维度 | 行为选项 |
| --- | --- |
| 默认怎样开始 | 快速确认已知再定起点；先例子和直觉；先整体框架和定义；按主题决定 |
| 默认怎样互动 | 讲解为主、关键节点检查；问题引导；先尝试再逐级提示；连续讲；按主题决定 |
| 默认详细程度 | 先简洁全貌再深入；逐步详细；直接进入较深细节；按主题决定 |
| 默认怎样巩固 | 关键节点短练习；更频繁检查；只在用户要求时测验；按主题决定 |

可临时显示 `1B 2A 3C` 等编号；编号、问卷原文和选项目录版本不落盘。每组的“按主题决定”
表示删除该维度的全局默认；重跑时必须在 diff 中明确显示。

自由讲述可以覆盖语言与术语、公式、代码、图表、反例、互动、外部资料与来源的呈现方式和
可访问性。不要询问姓名、年龄、职业、兴趣大全、全局能力等级、当前主题或截止时间。

映射规则：

- 面向未来的长期要求进入 `明确偏好`；
- 带条件、结果和适用范围的既往体验进入 `教学反馈`；
- 只针对当前主题或本轮的要求不保存；
- 身份、诊断和解释原因默认不保存，只提取可执行行为；
- 不完整教学反馈不能靠模型补造；至多追问一个必要问题，仍不完整则首次不保存、重跑保留旧条目；
- 不保存 VARK、视觉型/听觉型、MBTI、智力或能力标签；将它们转成具体行为问题再确认；
- 真实可访问性适配不能被当成伪学习风格忽略，默认只保存需要采取的行为；
- 允许或禁止联网属于权限，不写入 Learning Guidance；一手来源、关键链接等呈现偏好可以保存。

自由文字只在同一行为维度且适用范围重叠时高于菜单；更具体的条件规则可以与一般默认并存。
最终只展示并保存用户确认的自然语言 Markdown diff。

## Git 与 Obsidian

先说明 Git 在这里用于本地版本快照和恢复，不是云同步。任何选项都不会自动登录托管账号、
创建 GitHub/GitLab 仓库或上传内容；远端备份必须由用户另行明确要求。

新独立 Vault 用结果导向的名称提供三种选择，内部值只放在括号中：

1. **自动建立安全版本快照（`managed/true`，推荐）**：init 创建本地 Git 仓库和初始版本快照；以后
   只有不会混入用户已有改动时，才为本次保存自动创建版本快照；条件不安全时跳过，不把
   其他改动一起提交。适合希望保留可回退历史、又不想手动管理 Git 的用户。
2. **只建立初始版本（`managed/false`）**：init 创建本地 Git 仓库和初始版本快照；以后保存内容但
   不自动创建版本快照，版本管理由用户自己处理。
3. **不让 LearnEverything 使用 Git（`off/false`）**：不初始化仓库、不提交；Vault 的 Markdown
   读写和 Obsidian 使用不受影响。

首次用户选择“默认”时，在 dry-run 前用一句自然语言复述实际结果，例如“建立本地 Git baseline，
以后只在安全条件满足时自动提交；不设置远端、不上传”。所有 Git 选项之后都可通过显式重配
修改，但仍受下述仓库边界约束。

首次 existing 注册固定为 `off/false`。用户自行把 marker 和 Home 提交到 Vault 根仓库后，重跑
才可选择 `external`。目标位于父 Git 仓库中时必须使用 off，不能创建嵌套仓库或提交父仓库。

是否在完成后打开 Obsidian 是当次 UI 选择，不写进配置。init 不创建 `.obsidian/`，不安装主题、
插件或 CSS。

## 计划、确认与执行

1. 调用 `vault init ... --dry-run --format json`；
2. 展示模式、绝对路径、locator 变化、文件动作、ignored paths、Learning Guidance diff、Git
   动作、警告和一句数据契约：“只保存完成且确认的学习、明确偏好和直接反馈；中断学习不保存”；
3. 用户确认后，用完全相同参数去掉 `--dry-run`，加入
   `--expect-plan <plan_hash>`；
4. 如果返回 `PLAN_MISMATCH`，说明状态已经变化，重新 dry-run 和确认，不能执行新计划；
5. CLI 成功后，可选 Learning Guidance 作为独立 Markdown 数据控制 patch 写入。写前重读
   profile/Home/backlinks 并核对预览 hash；不匹配就重新展示 diff；
6. profile patch 失败时保留有效 Vault，准确报告“Vault 已初始化，学习指导尚未保存”；
7. 两个子结果都结束后，才按预览选择打开 Obsidian。

重跑时按“保留、新增、替换、删除”展示 profile diff；语义等价保留原文，不为润色制造 commit。
整体 init 只有机械计划和 profile diff 都为空时才报告 no-op。

用户在未完成学习中要求 init 时，先说明当前学习仍未保存。切换后继续学习则从新 Vault 重新
检索；未来只有完成并再次确认后才保存到新 active Vault。
