# 完成保存、语义审阅与数据控制

只在用户已经通过完成门槛并明确确认保存，或用户显式要求维护/审阅 Vault 时读取本文件。

## 保存前增量语义审阅

在任何学习结果写入前，自动审阅本次拟创建或修改的页面、learning record、同名/alias/全文
重复候选以及一跳链接和反链页。检查：

- 重复、同义或边界重叠概念；
- 互相矛盾、被新证据推翻或可能过时的解释；
- 过宽、过碎或只有标题的页面；
- 缺失关键链接、错误关系或孤立 map；
- profile 中一次性指令、跨分区重复、不完整反馈、相反反馈和人格化推断；
- 来源与正文不一致或证据不足的 claim。

发现候选问题时先自行处理：

1. 读完整相关页面、人工内容、learning records 和已有来源，区分矛盾、适用条件差异、历史变化
   和措辞差异；
2. 先用模型能力和本地证据形成判断；页面边界、命名和用户偏好不做无意义联网搜索；
3. 时效性强、高风险、来源冲突或直接决定本次核心结论但证据不足的事实必须查一手/权威来源；
   其他事实按不确定性选择性核查；
4. 不改变已交付语义的措辞、链接、来源元数据或组织细节可以直接修正拟写内容；
5. 如果核查改变核心 claim、完成项或适用边界，先交付纠正后的教学并重新等待“结束并保存”；
6. 仍有重要页面取舍或证据不足时，才把本地证据、联网证据、推荐方案、理由和备选项交给用户。

外部事实由证据约束，不由投票决定。用户决定是否保存、怎样拆分/合并页面、人工观点怎样保留，
以及证据不足时是否缩小或取消变更。高风险或核心事实仍不足时降低表述、加入条件或取消保存。

联网 query 只发送去上下文化后的最小 claim，不发送 profile、learning record、Vault 路径或身份
信息。用户当前明确禁止联网时服从；网络不可用时按证据不足降级。实际影响结论的 URL、标题和
访问日期写入相关页面；搜索结果页、网页全文和临时研究笔记不落盘。

无具体重要问题时，增量审阅不是额外确认 gate，也不保存审阅报告。

## 批次写入

1. 精确定位 Vault。未配置或 locator 无效时，先完成显式 init 的路径必要子集；用户拒绝则
   报告“学习已完成，但没有保存”。
2. 运行一次全库结构 lint。已有 error 时不写学习结果；报告诊断，等待用户单独授权修复。
3. 读取 Home、相关 knowledge、可能受影响的 profile、aliases、backlinks 和现有页面全文。
4. 形成完整变更集：更新/新建 knowledge，按需更新 profile，最后新增一个 learning record。
5. 执行上面的增量语义审阅并处理分流。
6. 冻结变更集，记录所有目标文件的精确 preimage/hash 和 Git dirty/staged 状态；这些只存在于
   当前进程或 Vault 外临时空间，结束即删除。
7. 写前重读；preimage 不匹配就重新合并和审阅，必要时重新确认，不能覆盖新人工内容。
8. 尽量用一次多文件 patch 写入。首次创建、重命名或删除 Learning Guidance 时，同批维护 Home；
   删除任何页面前处理全部 managed 与非-managed backlinks。
9. 再次运行全库 lint。失败时先修本次变更；无法修复则恢复精确 preimage、删除本批新文件。
   无法安全恢复时报告“不完整 Vault”和具体路径，不能声称保存成功。
10. 检查限定路径 diff，确认没有原始对话、临时文件或无关改动。
11. 仅在 marker 的 Git mode 不是 off、baseline 有效、auto-commit 为 true、lint 通过、目标文件
    操作前干净且 index 没有预存 staged 变化时，stage 本次明确路径并提交。禁止 `git add .`。

commit message：学习保存用 `learn: <主题> (<日期>)`；数据控制用 `vault: <操作>`。

Git commit 失败不撤销已经成功写入的 Markdown，但要恢复操作前 index，并准确报告“内容已保存，
版本快照未创建”。无法恢复 index 时报告残留 staged 路径。

保存回执应说明：learning record 路径、创建/更新的 knowledge/profile、lint 结果、增量语义审阅
范围，以及 Git commit 或跳过/失败原因。它是当前回复，不写成运行状态。

## 写入内容边界

- learning record 不保存 raw chat、逐题答案、诊断过程、未解决范围或逐轮状态；
- 它表达“内容已交付并确认结束”，不表达掌握；
- 重复学习同一主题新增 record，同时局部合并相关 knowledge；
- knowledge 更新前读完整文件，保留本次范围外人工内容；
- 一次性“这次讲快点”不进 profile；只有明确长期意图进入 `明确偏好`；
- 学习中的长期偏好或直接反馈随本次完成保存；用户要求“现在就永久记录/撤销”时可作为独立
  数据控制立即修改，但不能伪造 learning record。

进程仍在时对普通 lint 失败尽力精确回滚；首版不承诺多文件写入中途进程崩溃后的自动恢复。
下一次 lint 和 Git working tree 必须能暴露半写入。

## 全库深度审阅

用户可以显式要求“检查知识库”。也可在以下自然边界建议，但是否开始由用户决定：

- 新增 learning record 后总数到达新的 10 的倍数；
- 局部审阅或检索发现问题可能影响更多页面；
- 准备创建跨多个领域的大型 map 或综合结论；
- 用户准备基于知识库做重要决策或输出。

没有后台 timer、daemon 或持久审阅状态。长期未访问页面不会只因时间流逝自动审阅。

全库审阅先用本地页面形成候选，再按增量规则核查必要外部事实。默认在对话中按影响和可信度
报告，不修改文件。用户批准修复后，把它作为独立数据控制：局部修改、lint、限定 diff、按 Git
规则提交；不新增 learning record，也不递归触发另一轮全库审阅。

若用户暂不修复高影响问题，给三个清楚选择：立即修复、在受影响页加入可见待核查提示、或不
持久化本次发现。最后一种意味着后续不保证记得。

## 纠正、重命名与遗忘

- 重命名保留稳定 ID，并在同一变更更新 wikilinks；
- 拆分/合并明确旧页面去向和所有受影响链接；
- 删除 knowledge 前列出 backlinks；若 learning record 的 `本次沉淀` 因此失去全部有效链接，
  必须让用户选择改指向另一个语义准确页面，或同时纠正/删除该 record；
- 默认删除 learning record 不自动删除已沉淀进 knowledge 的当前知识；
- 删除作为教学反馈来源的 record 前，让用户选择删除反馈，或在明确重申后改成长期偏好；
- profile 重跑按“保留、新增、替换、删除”展示，语义等价保留原文；
- 可分别清空明确偏好、教学反馈或两个受管分区。保留用途不能确认的人工内容；页面真正为空且
  backlinks 已处理时才删除页面和 Home 入口；
- 普通文件删除不等于从 Git、同步端或备份历史彻底擦除。历史擦除是另一项高风险操作，首版
  不实现。
