# LearnEverything v1 Skill 设计

- 状态：v1 实现基线
- 更新日期：2026-08-28
- 规范角色：本文件是 v1 产品意图与 Skill/CLI 边界的唯一规范来源。
  [learning-state.schema.json](../schemas/learning-state.schema.json) 和
  [acceptance-scenarios.md](../evals/acceptance-scenarios.md) 是可执行的派生契约；若有
  冲突，以本文件为准并同步修正派生产物。

## 1. 产品中心

LearnEverything 是一个可以在任意 Codex 任务和任意工作目录中启动的长期学习
Skill。它首先帮助用户把一个新东西讲明白；诊断、检查、复习和记忆只服务于下一次
讲解，不取代讲解本身。

v1 的核心结果是：

1. 根据学习目的、已有知识和一次低摩擦诊断选择讲解起点；
2. 用适合当前主题的模型、例子、代码、公式、图或情景解释关键关系；
3. 用户没懂时立即换一种讲法，而不是只继续出题；
4. 学习可中断、可恢复，并停在真实的概念边界；
5. 保存少量会影响未来讲解的可检查、可纠正本地记忆。

本产品不输出分数、等级、掌握概率或“视觉型学习者”等人格标签。“本次目标已覆盖”
只表示承诺的解释已经交付，不表示用户已经掌握。

### 1.1 v1 非目标

- 跨设备同步；
- 多个 Codex 窗口同时教学；
- 多个并行开放学习会话；
- 题库、完整课程生成器或间隔复习系统；
- 精确知识追踪或掌握率模型；
- 原始对话、逐题历史或逐轮事件日志；
- 跨领域自动泛化教学偏好；
- 插件发布和团队共享。

## 2. 系统边界

~~~
任意 Codex 任务 / 任意 cwd
        │
        ▼
用户级 LearnEverything Skill ── 负责诊断、讲解、修复与收束
        │ JSON stdin/stdout
        ▼
本地 learn-everything CLI ───── 负责固定数据目录、校验与原子持久化
        │
        ▼
用户一次授权的数据目录 / SQLite
~~~

Skill 负责教学判断，CLI 不生成教学内容。CLI 只保存结构化压缩状态，并保证同一时间
至多有一个开放会话。数据目录由用户首次初始化时选择，此后不随项目目录变化。
等待授权或用户暂不授权不应阻塞讲解；这一分支必须明确说明尚未保存，也不能在之后把
临时教学内容静默回填到旧状态。

每次广泛学习先通过 `session get` 探测用户级配置和开放会话。只有
`NOT_INITIALIZED` 表示尚未完成一次性目录授权；成功结果直接复用。当前对话没有先前
授权消息、cwd 改变或 `STORAGE_UNAVAILABLE` 都不能被解释成“首次使用”。存储暂时
不可访问时可以请求当前运行环境访问已配置位置，但不能重新询问数据根、再次初始化或
静默切换目录。

## 3. 请求路由

### 3.1 聚焦问题

如果用户只是问一个具体问题，例如“为什么 softmax 要除以温度”，直接回答，不要求
开启学习会话、选择目标深度或完成三题诊断。已有开放会话不因此被覆盖或自动关闭。

### 3.2 新的广泛学习目标

当用户明确希望系统性学习一个主题时：

1. 先用 `session get` 探测持久化配置并检查开放会话；只有返回
   `NOT_INITIALIZED` 时才进行一次性目录授权和初始化；
2. 有开放会话时，先让用户选择恢复、暂停保留或关闭，不能静默覆盖；
3. 读取与主题和前置概念有关的本地记忆；
4. 明确命中既有主题时复用其 topic ID，否则生成可移植的 ASCII canonical slug；
5. 必要时补齐学习目的与目标深度，并完成起点诊断；
6. 形成少量本次完成条件；
7. 一句话说明讲解起点，并在同一回复立即开始第一段实质讲解。

### 3.3 恢复、暂停与关闭

- “继续上次学习”读取唯一开放会话并恢复；
- 用户明确暂停时保存 checkpoint；
- 达到目标后主动收束，由用户决定结束或扩展；
- 用户明确放弃时可以关闭未完成会话，但不能写成已经完成。

## 4. 起点诊断

广泛学习会话必须明确形成起点判断，不能因为历史记录存在就静默跳过诊断。

### 4.1 默认三道知识题

没有足够直接证据时，一次展示恰好三道简短的知识选择题。题目只检测会显著改变第一段
讲解的前置知识，避免测试枝节。目标深度选择不属于知识诊断，也不能替代其中一道。

每题都必须提供：

- “在看到选项前不知道，或主要靠猜”；
- 对不够简单的知识，再提供“我看不懂这些选项在说什么”。

这两个选项含义不同：前者表示无法独立回答，后者表示题目语言或前置概念本身已经
超出当前起点。不能把安全选项设计成羞辱性答案。

### 4.2 已有证据与拒答

- 用户在当前请求中已经给出等价诊断答案时，直接复用，不重复提问；
- 相关且近期的历史证据可以替代重复题目；只有关键前置仍陈旧、矛盾或不确定时才问一道窄确认，但不能省略明确的起点判断；
- 用户拒绝诊断时，将关键前置标记为未知，从保守起点开讲，不让诊断成为帮助前的门槛；
- 只有答案互相冲突、无法选择安全起点时才追加问题，并简短说明原因。

诊断结果只保存“已确认的前置、仍不确定的前置、选定起点”三类摘要。完成后删除逐题
内容，不显示分数、等级或掌握率。

学习目的和目标深度也参与教学边界判断。若用户没有说明学习目的，用一个短选择补齐；
若用户没有明确说明目标深度或等价的预期结果，必须另给一道目标深度选择。它与三道
知识题语义独立、不计入三题，但应放在同一轮，不能先后堆叠两套问卷。主题名称或笼统
的“我想学/了解 X”不算深度选择，也不能根据知识诊断表现替用户决定想学到哪里。

需要等待回答时，先创建开放会话并原子保存同一组结构化问题，再输出问题；中断后应
恢复这组问题。此时 goal 可以尚未定稿 purpose 或 target depth。回答结算后才补齐
二者、生成 completion items 并进入实质讲解。

### 4.3 目标深度

target depth 只改变本次解释边界和练习自主度，不是能力等级。对用户应问“学完这次，
你希望自己能做到哪一步？”，并把固定含义改写成当前主题下可观察的结果，而不是展示
内部枚举或只有程度形容词的抽象等级：

| 值 | 本次承诺 |
| --- | --- |
| `orientation` / 建立地图 | 能说清它是什么、解决什么问题和关键概念如何关联；不要求走通完整工作过程 |
| `explain` / 讲清机制 | 能沿一个完整例子解释它如何及为何运作；不要求自己处理任务 |
| `apply` / 带提示使用 | 讲解后能按照步骤提示完成一个典型任务、判断或情景分析 |
| `independent` / 独立迁移 | 面对新案例能以较少提示判断如何处理、检查结果并识别常见失误或边界 |

目标深度题另有“不确定，请根据我的学习目的推荐并说明理由”。只有用户选择该项或明确
拒绝选择时，系统才按用户目的选择最低足够深度，并在开讲前说明本次边界。沉默、漏答
或中断不等于拒绝；恢复时继续同一道选择。用户已明确给出目标深度或等价结果时直接
映射，不重复提问。不得把 `independent` 自动当成所有学习的终点，也不得把其中的小
练习升级成掌握率考试。

## 5. 完成边界

### 5.1 何时产生 ID

诊断完成后，Skill 根据本次主题、目的和目标深度自动形成 1–5 条
“completion_items”，也就是本次的 “done_when”。这些 “dw-01”、“dw-02”
之类的 ID 只在当前会话内稳定存在，不来自全局课程库，也不展示给用户。

例如“看懂 Q/K/V 公式”可以在诊断后形成：

~~~yaml
completion_items:
  - item_id: dw-01
    description: 解释 Q、K、V 分别由什么产生以及各自作用
    status: pending
  - item_id: dw-02
    description: 解释 QKᵀ 如何形成相关性分数以及 softmax 的作用
    status: pending
  - item_id: dw-03
    description: 用一个小例子解释权重如何组合 V
    status: pending
~~~

### 5.2 可以调整什么

讲解顺序、表示方式、例子、补充的前置桥梁和当前焦点可以随用户反馈变化，不需要修改
完成条件。用户明确扩展目标时，只追加新的未覆盖项；语义等价改写保留原 ID。

v1 不实现完成项拆分、合并后的覆盖迁移，也不维护 “scope_revision”、
“coverage_migration” 或 “supersedes”。如果目标发生根本变化，应关闭旧目标并新开
会话，而不是让模型充当数据库迁移器。

### 5.3 覆盖不是掌握

完成项只有 “pending | covered” 两态。只有确认相应解释已经进入交互上下文后才能
标为 “covered”；答对一道题、模型准备好了一段回复或用户沉默都不能代表覆盖，更不
代表掌握。

## 6. 解释协议

### 6.1 每个讲解单元

每个有意义的讲解单元应当：

1. 明确当前要弄懂的核心关系；
2. 给出一个足够清晰的解释模型；
3. 选择能让该关系可见的表示；
4. 用工作示例、执行过程或具体情景落地；
5. 根据用户反馈决定下一段，而不是机械执行预生成课程。

公式、代码、执行追踪、表格、类比、情景计算和图都只是候选表示。Skill 先判断主题
中最重要的关系，再选表示，不能因为 Attention 示例使用公式就把所有主题都套成公式
课。算法、系统、编程、金融和概念性主题应采用各自自然的解释方式。

首次使用用户可能不熟悉的英文缩写时，同时给出英文全称和简短中文释义；同一会话中已经定义过
则不机械重复。

当结构、流向、层级或时序用纯文字难以看清时，优先补一张紧凑图；图必须服务于当前
关系，不能为了“丰富形式”而增加装饰。

### 6.2 检查与练习

小检查只在答案会改变下一步讲法时使用，例如区分“概念没懂”和“计算失误”。它不是
每段解释后的固定仪式，也不能连续把学习变成问答。用户要求继续听解释时，优先解释。

## 7. 困惑修复

用户指出具体卡点时，直接改变相应解释：补前置、定义术语、填推理跳步、替换例子、
降低抽象程度或增加细节。

用户只说“没懂”“太难”时，同一回复先给一段明显不同、更安全的简化解释；若仍需
定位，可以在后面附至多一个短选择。不能只回复“你哪里没懂？”而不提供帮助。

当前用户的明确反馈始终覆盖旧适配记忆。修复可以改变教学路径，但不能静默缩小原目标
或把相邻主题自动加入课程。

## 8. 主动收束

当所有完成项均已覆盖时，Skill 应：

1. 明确告诉用户“本次设定的目标已经覆盖”；
2. 给出与主题复杂度相称的紧凑合成；
3. 只列真实存在的未解决问题；
4. 提供结束、继续巩固或明确扩展目标的低摩擦选择。

相邻知识只能作为可选下一目标，不能自动延长当前课程。若用户已经清楚地提出一个新
主题，可以在说明后关闭旧会话并新开；若原目标尚未覆盖，则先确认暂停还是放弃。

## 9. 暂停与恢复

checkpoint 只保存恢复真正需要的内容：

- 学习目标与完成项；
- 已确认交付的压缩摘要；
- 未解决困惑；
- 本会话有效的教学备注；
- 当前焦点和精确下一步；
- 最后一个尚未确认送达的讲解单元。

### 9.1 未确认单元

Codex 无法在回复已经显示给用户之后可靠地再执行一次保存。v1 使用一个精简的
“unconfirmed_unit” 解决这个边界：

1. 输出前保存当前已确认状态和即将发送单元的短摘要；
2. 下一条用户消息进入上下文时，再结算该单元及其可能覆盖的完成项；
3. 如果中间异常退出，恢复时保守重述这一单元。

它只需要 “summary” 和 “may_cover”，不保存完整回复，也不实现
通用 “intended_updates” 补丁系统。最坏情况是重复一段，不能跳过一段从未送达的
解释。

等待首轮选择答案时，三道知识题和未决的目的/目标深度选择一起保存在
“diagnosis.awaiting_answers”，不再套一层 diagnostic pending。诊断完成即删除题目；
知识题只留起点摘要，目标选择只结算到 goal，不混入前置知识摘要。

### 9.2 恢复体验

恢复时先用几句话重定位目标、已确认边界和未解决问题，再从 “next_move” 继续。
不得重新运行默认三题诊断、播放完整历史或只说“继续学习”。若存在
“unconfirmed_unit”，先重述或确认该单元。

如果会话仍处于 “awaiting_answers”，恢复同一组尚未完成的选择题，而不是重新生成
另一组诊断题；这一分支没有 teaching state 或 unconfirmed unit。

若用户在回答完成前明确放弃或切换主题，关闭命令只清除这个未完成会话，不写主题记忆、
概念笔记或适配证据。这样既释放唯一会话槽，也不会把尚未发生的教学伪装成学习结果。

## 10. 长期记忆

只持久化能够改变未来讲解、恢复位置或用户数据控制的状态。

### 10.1 四类记忆

1. **显式偏好**：用户明确提出的、带作用域的教学要求，立即生效；
2. **概念笔记**：用户声明或学习中直接观察到的前置知识摘要及依据；
3. **主题记忆**：会话关闭后才写入的中心模型、已覆盖概念、未解决问题、建议下一步及可选来源链接；
4. **适配信号**：某种讲法在窄作用域和条件下是否值得优先尝试。

主题记忆按稳定 topic ID upsert。重复学习同一主题时，关闭前合入仍然有效的既有中心
模型；当前纠正优先，不能用一次更窄或提前停止的会话抹掉早先仍有用的摘要。

开放会话是当前进度的唯一事实来源。当前会话尚未关闭时，不能把同一进度复制进主题
记忆。

不保存原始对话、完整题目历史、孤立答题结果、人格标签或没有决策消费者的
“confidence”。

### 10.2 最小适配生命周期

显式偏好与推断信号分开处理。显式偏好立即采用；推断信号采用最小生命周期：

- 一次明确的直接帮助反馈形成 “candidate”；
- 另一个会话再次获得明确直接支持后提升为 “active”；
- 明确的负反馈立即停止当前会话采用，并把长期信号降为 “inactive”；
- 后续新的明确正向反馈可以把 inactive 重新置为 candidate；
- 用户可以随时 inspect、correct 或 forget。

“candidate” 只允许在精确匹配的作用域和条件下做一次低成本尝试；“active” 才能在
没有当前反馈冲突时作为表示方式的默认决胜因素。阶段本身已经表达一条还是两条独立
支持证据，因此不再另存与 status 一一重复的 support count。

信号只表达“在某个 scope/condition 下优先尝试某个 strategy”。沉默、一次答对、
模型自己的猜测或跨领域类比都不能计为支持证据。

v1 不保存 generation、历史版本、自然过期时间、weak/direct 双阈值、缓存
“effective_status” 或 session override 表。当前会话中的直接反馈写入
“local_teaching_notes”，始终优先于长期信号。

### 10.3 读取与更新

- 新会话和恢复时只读取当前主题、少量前置概念及匹配的适配信号；
- 每个讲解单元使用已加载上下文调整表示顺序，但内容本身优先；
- 会话关闭时最多提交 0–3 条有直接依据的适配观察；没有证据就不提交；
- 被纠正或遗忘的数据在下一讲解单元前重新读取，并清理开放会话中与之冲突的局部推断，
  不能继续使用旧结论驱动讲法。

## 11. 最小持久状态

~~~text
schema_version

learner
  explicit_preferences[]
  concept_notes[]
  adaptation_signals[]

topic_memories[]                 # 只含已关闭会话

open_session?
  session_id
  topic_id
  topic_title
  status                         # active | paused
  revision
  goal
    purpose
    target_depth
    completion_items[1..5]
  diagnosis                      # awaiting_answers | complete
  teaching_state
    confirmed_summary
    unresolved_confusions[]
    local_teaching_notes[]
    current_focus
    next_move
  unconfirmed_unit?
  created_at
  updated_at
~~~

逐题知识诊断与未决目标选择只在 “awaiting_answers” 时存在；此时 purpose 和 target
depth 可以尚未定稿。诊断完成后，二者、完成项和 teaching state 才同时成为必需。具体条件约束见
[learning-state.schema.json](../schemas/learning-state.schema.json)。

### 11.1 写入一致性

- SQLite 事务和唯一约束保证至多一个开放会话；
- 每次会话变更携带一个 “expected_revision”，冲突时拒绝 stale write；
- learner/topic 数据修正各自在一个事务中完成，下一教学轮重新读取 context；
- 不再维护 “store_revision”、claim token 或租约。

ID 只要求在所属数组或会话内唯一；completion item ID 可以在不同会话复用。
“selected_option_id” 只引用同一道题的选项，“may_cover” 只引用当前开放会话的完成项。
“last_evidence_session_id” 是适配证据的来源标识，不要求对应会话仍被长期保存。

v1 的已知限制是两个窗口可能同时生成回复，但后写者不能静默覆盖新状态。完整多窗口
教学所有权协议留到后续。

## 12. CLI 契约

最小命令面：

~~~text
learn-everything init --data-root <path>
learn-everything context get --input -
learn-everything session get
learn-everything session start --input -
learn-everything session checkpoint --expected-revision <n> --input -
learn-everything session close --expected-revision <n> --input -
learn-everything data inspect [--input -]
learn-everything data correct --input -
learn-everything data forget --input -
~~~

所有结构化输入输出使用 JSON。CLI 必须：

- 校验输入并返回机器可判定错误；
- 原子写入会话和关闭后的主题记忆；
- 对用户明确放弃的未完成诊断原子清槽，但不制造主题记忆；
- 只返回请求所需的相关上下文；
- 不生成问题、解释、分数或教学建议；
- 不依赖调用时的 cwd。

v1 只需要区分：未初始化、已有开放会话、没有开放会话、输入无效、revision 冲突和
存储不可用。导出、租约和十余种故障码不属于首个纵向切片。

## 13. Skill 包结构

~~~text
learn-everything/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── references/
│   └── state-and-cli.md
└── scripts/
    └── learn-everything
~~~

“SKILL.md” 保留请求路由、诊断、解释、修复、收束、暂停恢复和适配使用底线。
“state-and-cli.md” 只在初始化、持久化、恢复或数据控制时读取。CLI payload、SQLite
结构和 revision 处理不进入每轮教学上下文。

不创建占位 assets、重复 README、通用教学百科或四套相互引用的 reference。实际
Skill 入口预计约 80–140 行，但以保留关键行为约束为准，不把行数当目标。

这一结构遵循官方 Skill 的渐进披露方式：
[OpenAI Docs — Build skills](https://learn.chatgpt.com/docs/build-skills)。

## 14. 故障降级

存储失败不能阻塞当下的讲解。Skill 应明确说明：

- 当前仍可继续学习；
- 本轮状态没有被可靠保存；
- 之后可能无法从准确位置恢复。

不得在写入失败时声称“已经保存”，也不得把临时讲解静默合并进旧 checkpoint。
存储恢复后先重新读取唯一开放会话，再由用户决定继续位置。

## 15. 验收与发布门槛

详细行为场景只维护在
[acceptance-scenarios.md](../evals/acceptance-scenarios.md)，讲解质量使用
[explanation-quality-rubric.md](../evals/explanation-quality-rubric.md)。

v1 发布必须真实验证：

- 聚焦问题不会被强制开课；
- 三题诊断与两个安全选项；
- 未明确目标深度时，同轮出现一道独立、结果导向且不替代知识题的深度选择；
- 一句话起点说明后立即实质讲解；
- 多领域解释不会被公式模板绑架；
- 用户没懂时同轮获得改变后的解释；
- 完成边界稳定且不会自动扩课；
- 暂停、异常中断与恢复；
- 唯一开放会话不被覆盖；
- 适配信号可以提升、降级、纠正和删除；
- 从不同 cwd 调用仍访问同一授权数据目录；
- 存储故障不会被伪装成成功。

## 16. 首个实现切片

1. 以精简 0.2 schema 和一个暂停 fixture 固定数据契约；
2. 实现 init、context、session 和 data control 的最小 CLI；
3. 创建用户级 Skill 及一份 state/CLI reference；
4. 运行核心 acceptance scenarios 和讲解质量 rubric；
5. 在两个不同项目目录、一个中断恢复案例和至少四类主题上前向测试；
6. 根据真实失败做窄修正，不为尚未发生的边缘情况继续扩展状态机。
